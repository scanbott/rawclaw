# Raw Claw -- One-Command Client Setup Specification

**Version:** 1.0 | **Date:** 2026-03-30
**Author:** Alexander Alberts (CTO)
**Purpose:** Design document for `rawclaw setup` CLI that scaffolds a complete client deployment

---

## Goal

Replace the current manual process (copy Dineline files, search-and-replace names, manually create Supabase tables, manually generate .env files) with a single command:

```bash
rawclaw setup \
  --client "Acme Corp" \
  --slug acme \
  --seats 3 \
  --seat "Nick:technical" \
  --seat "Brett:ceo" \
  --seat "Jace:coo" \
  --integrations hubspot,meta-ads,stripe,clickup,slack \
  --supabase-url "https://xxx.supabase.co" \
  --supabase-key "eyJ..."
```

**Output:** A complete `rawclaw/clients/acme/` directory with everything needed for install day.

---

## What the Command Should Do

### Step 1: Validate Inputs

- Client name and slug are provided and valid (slug is lowercase, URL-safe)
- Seat count matches number of `--seat` flags
- Each seat has format `name:role` where role is one of: `ceo`, `coo`, `technical`, `employee`
- At least one seat with `ceo` or `coo` role
- Integrations are from the supported list
- Supabase URL is reachable (if provided)

**Error behavior:** Fail fast with clear error message. Do not create partial output.

### Step 2: Create Client Directory

```
rawclaw/clients/{slug}/
  README.md                          -- Client overview (auto-generated)
  intake-form.md                     -- Copy of template, pre-filled where possible
  pre-install-checklist.md           -- Copy of template
  install-notes.md                   -- Blank template for install day
  .env.example                       -- All required keys with placeholders
  env/

    .env.{seat2}
    .env.{seat3}
  supabase/
    001_core_schema.sql              -- Copy from dineline/supabase/
    002_{slug}_tables.sql            -- Generated from template with slug substitution
    003_rls_policies.sql             -- Copy (generic, not client-specific)
    004_seed_{slug}.sql              -- Generated: company row + seat rows + API connections
    005_security_fixes.sql           -- Copy
  templates/
    CLAUDE-{seat1}-{role1}.md        -- Populated template per seat
    CLAUDE-{seat2}-{role2}.md
    CLAUDE-{seat3}-{role3}.md
  getting-started/
    getting-started-{seat1}.md       -- Per-seat guide (template with name/role filled)
    getting-started-{seat2}.md
    getting-started-{seat3}.md
  monitoring/
    heartbeat.py                     -- Copy from dineline/monitoring/
    api_health.py
    uptime_report.py
    launchd/                         -- Copy of plist templates
  integrations/
    base.py                          -- Copy from dineline/integrations/

    generate_env.py                  -- Copy from dineline/setup/
```

### Step 3: Generate Supabase Seed SQL

From the `--seat` flags, generate `004_seed_{slug}.sql`:

```sql
-- Auto-generated by rawclaw setup
-- Client: {client_name}
-- Date: {date}

-- Company
INSERT INTO companies (name, slug, created_at)
VALUES ('{client_name}', '{slug}', now())
ON CONFLICT (slug) DO NOTHING;

-- Seats
INSERT INTO seats (company_id, name, role, created_at)
SELECT c.id, '{seat1_name}', '{seat1_role}', now()
FROM companies c WHERE c.slug = '{slug}'
ON CONFLICT DO NOTHING;

INSERT INTO seats (company_id, name, role, created_at)
SELECT c.id, '{seat2_name}', '{seat2_role}', now()
FROM companies c WHERE c.slug = '{slug}'
ON CONFLICT DO NOTHING;

-- ... repeat per seat

-- API Connections (based on --integrations flag)
INSERT INTO api_connections (company_id, service_name, status, created_at)
SELECT c.id, '{integration}', 'pending', now()
FROM companies c WHERE c.slug = '{slug}'
ON CONFLICT DO NOTHING;
```

### Step 4: Generate Per-Seat .env Files

Use the same template logic as `dineline/setup/generate_env.py` but in batch mode:

- CEO/COO seats get `SUPABASE_SERVICE_KEY`
- Technical/Employee seats get `SUPABASE_ANON_KEY` + `SEAT_ID`
- Only include integration keys that match `--integrations` flag
- All values are placeholders (e.g., `HUBSPOT_API_KEY=__REPLACE_ME__`)
- If `--supabase-url` and `--supabase-key` are provided, fill those in

### Step 5: Populate CLAUDE.md Templates

For each seat, copy the matching `CLAUDE-{role}.md` template and replace:

| Placeholder | Value |
|-------------|-------|
| `{{CLIENT_NAME}}` | Client name |
| `{{CLIENT_SLUG}}` | Slug |
| `{{SEAT_NAME}}` | Seat holder's name |
| `{{SEAT_ROLE}}` | Role |
| `{{COMPANY_DESCRIPTION}}` | `"[FILL IN]"` (Dilan completes later) |
| `{{SUPABASE_PROJECT_ID}}` | Extracted from Supabase URL (if provided) |

### Step 6: Generate install-commands.md

Pre-build the exact `setup.sh` commands for each seat:

```markdown
# Install Commands for {Client Name}

\`\`\`bash

  --tailscale-key __REPLACE_WITH_TSKEY__
\`\`\`

## Seat 2: {Name} ({Role})
...
```

## CLI Design

### Full Argument Reference

```
rawclaw setup [options]

Required:
  --client NAME          Company name (e.g., "Acme Corp")
  --slug SLUG            URL-safe identifier (e.g., "acme")
  --seats N              Number of seats (1-10)
  --seat NAME:ROLE       Seat definition (repeat per seat)
                         Roles: ceo, coo, technical, employee

Optional:
  --integrations LIST    Comma-separated integration list
                         Options: hubspot, salesforce, ghl, meta-ads,
                         google-ads, tiktok-ads, stripe, clickup, asana,
                         notion, slack, discord
  --supabase-url URL     Supabase project URL (fills into .env files)
  --supabase-key KEY     Supabase service role key (fills into .env files)
  --output-dir PATH      Output directory (default: rawclaw/clients/{slug}/)
  --template-dir PATH    Custom template directory (default: dineline/)
  --dry-run              Show what would be created without writing files
  --force                Overwrite existing client directory if it exists
  --verbose              Print every file as it's created
```

### Subcommands (future)

```
rawclaw setup    -- Scaffold a new client
rawclaw validate -- Run pre-install validation on a client directory
rawclaw deploy   -- Deploy to Mac Minis via SSH (wraps setup.sh)
rawclaw status   -- Check agent health across all clients
rawclaw list     -- List all client directories and their status
```

## Template System

### 002 Client Tables Template

The `002_{slug}_tables.sql` is generated from a base template. The Dineline version has Dineline-specific tables (hubspot_contacts, campaigns, scorecards). The generic version should:

1. Always include: `client_contacts`, `campaigns`, `scorecards`, `meeting_prep`, `playbook_items`
2. Conditionally include based on integrations:
   - `--integrations hubspot` adds `hubspot_contacts` table
   - `--integrations stripe` adds `payment_events` table
   - `--integrations meta-ads` or `google-ads` adds `ad_campaign_metrics` table
   - `--integrations clickup` or `asana` adds `project_tasks` table

### CLAUDE.md Template Variables

All templates use `{{VARIABLE}}` syntax. The template engine does a single pass of string replacement:

```python
VARIABLES = {
    "CLIENT_NAME": args.client,
    "CLIENT_SLUG": args.slug,
    "SEAT_NAME": seat.name,
    "SEAT_ROLE": seat.role,
    "SEAT_ID": f"__SEAT_ID_{seat.name.upper()}__",  # Filled after Supabase seed
    "COMPANY_DESCRIPTION": "[FILL IN DURING INTAKE]",
    "SUPABASE_PROJECT_ID": extract_project_id(args.supabase_url) or "__REPLACE__",
    "INTEGRATIONS_LIST": ", ".join(args.integrations),
}
```

## Validation Rules

| Check | Error Message |
|-------|--------------|
| Slug contains spaces or uppercase | "Slug must be lowercase and URL-safe (a-z, 0-9, hyphens only)" |
| Seat count doesn't match --seat flags | "Expected {N} --seat flags but got {M}" |
| Unknown role in --seat flag | "Unknown role '{role}'. Use: ceo, coo, technical, employee" |
| Unknown integration | "Unknown integration '{name}'. Available: {list}" |
| No CEO or COO seat | "At least one seat must have role 'ceo' or 'coo'" |
| Output directory exists and --force not set | "Directory already exists: {path}. Use --force to overwrite" |
| Supabase URL invalid format | "Supabase URL should be https://{project-id}.supabase.co" |

## Migration Path from Dineline

The current Dineline deployment was hand-crafted. To make the system generic:

1. **Phase A (now):** Extract Dineline-specific values into templates with placeholders
2. **Phase B (build CLI):** Write `rawclaw/cli.py` + `scaffold.py` + `sql_generator.py`
3. **Phase C (test):** Generate a fresh "test-client" and verify all files are valid
4. **Phase D (validate):** Use the CLI to re-generate the Dineline directory and diff against the original
5. **Phase E (ship):** Use for the next real client

**The Dineline directory stays as-is.** It's the reference implementation. New clients are generated by the CLI into `rawclaw/clients/`.
