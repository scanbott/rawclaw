# Workspace Structure

Every Rawclaw install uses this directory layout. Agents know where things live. Don't invent new top-level folders.

```
rawclaw/
├── agents/           Agent configs (CLAUDE.md + agent.yaml per agent)
├── skills/           Skill library (each skill is a folder with SKILL.md)
├── knowledge/        Everything the agents know about the business
│   ├── client/       Client's own business data (auto-populated on setup)
│   ├── frameworks/   Pre-loaded expert methodology (copy, funnels, sales)
│   └── competitors/  Competitor intel (scraped on demand)
├── clients/          Client/customer tracking (if applicable)
│   └── _template/    Copy this to create a new client record
├── workspace/        Working directory for agent outputs
│   ├── artifacts/    Finished deliverables (copy, scripts, reports)
│   └── tmp/          Scratch space -- nothing permanent here
├── src/              Core engine (do not modify)
├── scripts/          Operational scripts
├── migrations/       Database migration history
└── docs/             Architecture and deployment guides
```

## File Placement Rules

| Output Type | Where It Goes |
|-------------|---------------|
| Finished copy / scripts | `workspace/artifacts/copy/` |
| Research reports | `workspace/artifacts/research/` |
| Funnel maps / strategy docs | `workspace/artifacts/strategy/` |
| Client records | `clients/[name]/` |
| Competitor profiles | `knowledge/competitors/[name].md` |
| Temp / scratch | `workspace/tmp/` only |
| Nothing | Project root (keep it clean) |

## knowledge/client/ Files

Auto-generated by setup wizard. Agents load these on every run.

- `business.md` -- What the business sells, ICP, transformation, pricing
- `brand-voice.md` -- Tone, words to use, words to avoid, examples
- `offer.md` -- Full offer stack, bonuses, guarantee, objections
- `team.md` -- Who's on the team, roles, contacts
- `assets.md` -- Links, tools, accounts, integrations
